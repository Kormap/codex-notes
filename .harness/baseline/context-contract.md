# Context Contract

이 문서는 Codex가 작업 컨텍스트를 해석할 때 `AGENTS.md`와 Harness가 담당하는 경계를 고정한다.

## 책임 경계

### AGENTS.md

- 시스템·사용자·프로젝트 지침 사이의 우선순위
- 기본 언어, 응답 형식, 작업 방식
- 수정 범위, 안전, 검증, 보고의 공통 행동 원칙
- 응답 프로필별 분석 관점과 운영 기준

### Harness

- 요청을 재현 가능한 작업 계약으로 구체화하는 방법
- 실행 범위와 성공 조건을 확인하는 방법
- 결과를 evaluator로 판정하고 모든 Harness 작업의 최소 trace 또는 강화 Harness의 확장 trace로 남기는 방법
- 반복 결과를 분석하고 개선안을 baseline으로 승격하는 방법
- 멀티·서브에이전트 사용 시 역할, 위임, 소유권, 통합 방법

`AGENTS.md`는 모든 Codex 작업에 적용한다. Harness baseline은 `AGENTS.md`만으로 재현성, 검증 증거, 또는 협업 통제가 충분하지 않은 작업에 추가 적용한다. Harness는 `AGENTS.md` 내용을 복제하거나 완화하지 않고, 그 행동 원칙을 실행·검증·개선 절차로 구체화한다.

## 적용 순서

작업에 적용할 기준은 다음 순서로 해석한다.

1. 시스템과 플랫폼의 안전 지침
2. 사용자의 현재 명시적 요청과 승인
3. 대상 프로젝트의 더 구체적인 지침과 확립된 관례
4. `AGENTS.md`의 공통 행동 원칙
5. 선택된 Skill의 세부 지침

Harness 대상 작업에는 다음 기준을 추가로 적용한다.

6. 현재 baseline과 승인·병렬 작업 같은 Harness 정책
7. 작업별 task와 evaluator
8. 최소 trace 계약
9. 조건에 따라 선택된 실행 역할, 추가 정책, 확장 trace 계약

아래 단계의 문서는 위 단계의 지침을 구체화할 수 있지만 충돌하거나 약화할 수 없다. 충돌하면 상위 지침을 따르고, 범위·안전·결과에 실질적인 영향이 있을 때 사용자에게 알린다.

`candidates/`의 내용은 평가 대상일 뿐 현재 작업 기준이 아니다. 명시적인 승격 전에는 baseline처럼 적용하지 않는다.

## Harness 대상 작업의 최소 컨텍스트

Harness를 적용하는 작업은 다음 항목을 확인한다.

- 목표와 기대 결과
- 허용된 변경 또는 조사 범위
- 확인이 필요한 중요한 불확실성
- 성공 조건과 검증 방법
- 적용할 trace 수준과 필수 근거
- 적용할 프로젝트 지침, Harness 문서, 실행 역할, Skill
- 사용자에게 보고할 근거와 남은 위험

데이터, 운영 동작, 외부 비용, 보안 또는 중요한 설계 결정에 영향을 주는 불확실성은 사용자 확인 없이 가정하지 않는다.
