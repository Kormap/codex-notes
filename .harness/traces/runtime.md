# Trace 실행 계약

Trace를 생성하거나 갱신하기 전에 이 문서와 선택한 template, [현재 version](../baseline/version.md)을 읽는다. 읽기 전용 작업은 기록 요청·승인이 없으면 trace를 만들지 않고 응답에 검증 근거와 한계를 남긴다. 응답만 있는 리뷰는 report source로 집계하지 않는다.

## 기록과 판정

- 시작 시 task·성공 조건·검증 방법·trace 수준을 정한다. 실행 중 재시도, 승인, 외부 행동과 역할 상태처럼 판정에 영향을 주는 사건을 요약해 갱신한다. 종료 후 기억에 의존해 재구성하지 않는다.
- `trace_id`는 `tr-YYYYMMDD-<slug>-<sequence>`, 파일명은 `<trace_id>.md`, 시간은 ISO 8601 `+09:00`을 사용한다. 저장소 안에서 ID를 중복하지 않는다.
- 같은 작업의 재시도는 기존 trace의 attempt·rework에 기록한다. 독립 비교 실행만 새 trace와 `run-<sequence>` 형식의 `run_id`를 가진다.
- template의 필드 키·구조·enum을 유지한다. 값 없음은 `NONE`, 조건 미적용은 `NOT_APPLICABLE`이다. 적용되지 않는 확장 섹션도 삭제하지 않는다. 여러 강화 조건은 확장 trace 하나에 합친다.
- 통합된 최종 상태에서 각 필수 검사를 실행하고 성공 조건에 연결한다. 하나라도 실패하면 전체 `FAIL`, 실패 없이 필수 판정이 불가능하면 `BLOCKED`, 모든 필수 조건 충족 시만 `PASS`다. 역할의 `COMPLETED`는 전체 `PASS`가 아니다.
- 정확한 명령·종료 결과·근거 요약, 미검증 항목과 남은 위험을 사용자 보고와 일치시킨다. 완료 시 필수 필드, 식별자, 민감정보와 결과 정합성을 확인하고 중앙 저장소의 `scripts/doctor.sh`를 실행한다. 진단 실패를 evaluator 통과로 대체하지 않는다.

## 저장과 민감정보

- 원본은 중앙 Harness의 `.harness/traces/runs/`에 저장하며 없으면 생성한다. 기본적으로 Git에 포함하지 않는다. 공개 가능한 저장소 상대 경로와 비민감 요약만 기록하고 전체 프롬프트·대화·긴 출력·비밀값·운영 데이터 원문은 기록하지 않는다.
- 마스킹 전 원문을 임시로라도 trace에 저장하지 않는다. 비밀값이 기록되면 공유·커밋을 중단하고 노출된 것으로 취급해 기존 보안 절차로 대응한다. 문자열 치환만으로 안전하다고 간주하지 않는다.
- 공유·보관 정리·report 원본 선택 시에는 [보관·마스킹 계약](README.md#보관과-git-정책)을 먼저 읽는다. 원본을 자동 삭제하지 않으며 report/candidate의 근거 보관 조건을 보존한다.

Schema·enum 자체를 변경하거나 상세 해석이 필요할 때는 [전체 trace 계약](README.md)을 읽는다.
