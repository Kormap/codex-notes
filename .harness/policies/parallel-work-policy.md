# Parallel Work Policy

이 정책은 플랫폼과 상위 지침이 멀티·서브에이전트 사용을 허용할 때 병렬 작업의 책임, 파일 소유권, 충돌 처리와 최종 통합 기준을 정의한다.

## Lead의 통합 책임

Lead는 멀티·서브에이전트 작업의 단일 통합 책임자다.

- 사용자 요청을 목표, 범위, 성공 조건으로 해석한다.
- 병렬화가 필요한지 판단하고 독립적인 작업 단위로 분해한다.
- 각 작업의 읽기 범위, 수정 가능 파일, 금지 행동, 검증 기준을 지정한다.
- writer와 파일 소유권을 배정하고 공유 작업 트리 또는 worktree 사용을 선택한다.
- 에이전트 결과와 변경을 검토해 채택, 재작업, 보류 여부를 결정한다.
- 충돌과 상충하는 판단을 해소하고 최종 변경을 통합한다.
- 통합된 상태에서 evaluator를 다시 실행하고 최종 완료 여부와 사용자 보고를 결정한다.

서브에이전트는 범위, 승인, 소유권, 최종 완료 여부를 독자적으로 확대하거나 확정하지 않는다. 불확실성이 자신의 계약을 넘어가면 작업을 확장하지 않고 Lead 결정 필요 사항으로 반환한다.

## 병렬화 기준

다음 작업은 결과가 독립적이고 통합 지점이 명확할 때 병렬화할 수 있다.

- 서로 다른 자료나 모듈의 읽기 전용 조사
- 독립된 변경 영역의 리뷰와 실패 원인 분석
- 명확히 분리된 파일을 수정하는 구현
- 서로 상태를 변경하지 않는 검증

다음 작업은 기본적으로 병렬 writer로 나누지 않는다.

- 동일 파일 또는 서로 강하게 결합된 파일의 수정
- 하나의 미확정 설계 결정을 전제로 하는 구현
- 이전 결과에 따라 다음 행동이 달라지는 순차 작업
- 승인 판단, 충돌 해결, 최종 통합과 최종 검증

병렬 실행의 이점이 불명확하면 Lead가 직접 수행하거나 순차 작업으로 구성한다.

## 파일 단위 단일 writer

- 한 시점에 하나의 파일은 한 writer만 소유한다.
- 여러 writer가 참여하면 Lead가 수정 가능 파일 또는 디렉터리를 겹치지 않게 명시한다.
- 소유권이 없는 파일은 읽을 수 있지만 수정하지 않는다.
- 공용 설정, lockfile, index, migration 목록처럼 다른 변경과 쉽게 충돌하는 파일은 Lead 또는 지정한 단일 writer가 통합한다.
- Reviewer와 Verifier는 별도 수정 권한을 받지 않는 한 읽기 전용이다.
- 작업 범위가 바뀌어 추가 파일 수정이 필요하면 먼저 Lead에게 소유권 변경을 요청한다.

## 공유 작업 트리와 worktree

공유 작업 트리는 수정 파일이 겹치지 않고 Lead가 소유권을 명확히 배정할 수 있을 때 사용한다. 다음 조건 중 하나라도 해당하면 별도 worktree를 우선 검토한다.

- 동일하거나 결합도가 높은 파일을 여러 구현안이 다뤄야 한다.
- 독립된 변경을 각각 검증한 뒤 선택적으로 통합해야 한다.
- 장시간 실행되는 변경이 다른 writer의 작업을 방해할 수 있다.
- 브랜치 단위 diff와 검증 결과를 분리해야 한다.

worktree를 사용해도 승인 정책과 파일 소유권은 유지한다. worktree 생성이 동일 파일 동시 수정의 충돌을 자동으로 해결하지 않으므로 Lead가 채택할 변경과 통합 순서를 결정한다.

## 충돌과 예상하지 못한 변경

- 다른 writer나 사용자의 예상하지 못한 변경을 발견하면 해당 파일의 수정을 중단한다.
- 기존 변경을 되돌리거나 덮어쓰거나 임의로 병합하지 않는다.
- 현재 상태, 충돌 파일, 자신의 변경 여부와 선택지를 Lead에게 보고한다.
- Lead는 소유권 재배정, 순차 통합, worktree 분리, 사용자 확인 중 적절한 방법을 선택한다.
- 충돌 해결 후에는 개별 검증 결과를 그대로 신뢰하지 않고 통합된 상태에서 관련 evaluator를 다시 실행한다.

## 공통 반환 계약

각 서브에이전트는 최소한 다음 내용을 Lead에게 반환한다.

- 결론과 수행 범위
- 근거 파일·라인 또는 판단 근거
- 변경 파일과 소유권 준수 여부
- 실행한 검증과 결과
- 검증하지 못한 항목과 남은 위험
- 현재 상태와 일시 중단·에스컬레이션 사유
- 작업 재개에 필요한 결정과 조건
- Lead가 결정하거나 통합해야 할 사항

상세 역할 문서는 [roles/README.md](../roles/README.md)와 각 역할 문서에서 이 공통 계약을 역할별로 구체화한다.
