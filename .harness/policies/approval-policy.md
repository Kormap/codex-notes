# Approval Policy

이 정책은 Codex가 요청 범위 안에서 불필요하게 멈추지 않으면서도 외부 상태, 데이터, 비용, Git 이력에 영향을 주는 행동은 사용자 승인 아래 수행하도록 경계를 고정한다.

## 행동별 기본 정책

| 행동 | 기본 정책 |
|---|---|
| 파일·코드·문서 읽기, 검색, 로그·상태 조회 | 요청 범위 안에서 별도 승인 없이 수행 |
| 요청된 로컬 소스·테스트·문서 수정 | 요청 범위 안에서 별도 승인 없이 수행 |
| 비파괴적 로컬 테스트·빌드·린트·정적 검사 | 요청 범위 안에서 별도 승인 없이 수행 |
| 임시 파일 생성과 작업 종료 후 정리 | 대상과 범위가 명확하고 복구 가능하면 별도 승인 없이 수행 |
| `git commit` | 실행 직전에 승인 요청하고 사용자의 명시적 확인 후 수행 |
| `git push` | 실행 직전에 승인 요청하고 사용자의 명시적 확인 후 수행 |
| PR 생성·수정·종료 | 실행 직전에 승인 요청하고 사용자의 명시적 확인 후 수행 |
| 운영·스테이징 DB DDL/DML, 데이터 backfill·정정 | 대상 환경과 변경 내용을 명시하고 승인 후 수행 |
| 배포, 롤백, 인프라·클라우드 상태 변경 | 대상 환경과 영향을 명시하고 승인 후 수행 |
| 외부 메시지 전송, 이슈·일정·문서·외부 API 상태 변경 | 대상과 변경 내용을 명시하고 승인 후 수행 |
| 구매, 유료 리소스 생성, 비용 증가 가능 행동 | 예상 비용이나 비용 발생 조건을 명시하고 승인 후 수행 |
| 요청 범위를 실질적으로 확대하는 변경 | 확대 이유와 추가 범위를 명시하고 승인 후 수행 |

`git commit`, `git push`, PR 생성·수정은 초기 요청에 포함되어 있거나 이전에 유사한 행동을 승인했더라도 바로 실행하지 않는다. 실제 실행 직전에 승인 요청을 제시하고 현재 작업에서 사용자의 명시적 확인을 받아야 한다. 여러 행동을 한 승인 요청에 포함할 수 있지만, 수행할 행동과 대상 저장소·브랜치·remote·PR을 빠짐없이 명시해야 한다.

## 승인 요청 계약

승인 요청에는 판단에 필요한 최소 정보를 포함한다.

- 수행할 행동
- 정확한 대상과 환경
- 예상되는 상태 변화와 영향
- 복구 가능 여부와 복구 방법
- 비용 또는 외부 노출 가능성

승인은 요청에 명시된 행동, 대상, 환경, 현재 작업에만 유효하다. 대상이나 영향이 달라지거나 새로운 위험이 발견되면 다시 승인받는다. 응답이 없거나 의미가 불명확하면 승인으로 간주하지 않는다.

## 파괴적 행동

파괴적 행동은 데이터, 이력, 리소스 또는 사용자 변경을 삭제·덮어쓰거나 복구하기 어렵게 만드는 행동이다.

- 사용자가 정확한 대상과 행동을 직접 요청했고 복구 가능한 경우에는 읽기 전용 확인으로 대상을 검증한 뒤 같은 승인을 반복해서 묻지 않는다.
- 복구 불가능하거나 외부·운영 데이터에 영향을 주는 경우에는 정확한 대상, 영향, 복구 불가 여부를 제시하고 실행 직전에 다시 확인한다.
- 대상이 모호하거나 요청보다 범위가 넓어지면 실행을 중단하고 확인한다.
- 가능한 경우 삭제보다 휴지통 이동, 백업, 새 버전 생성처럼 복구 가능한 방법을 우선한다.
- 사용자 변경을 임의로 되돌리거나 승인되지 않은 정리 작업에 포함하지 않는다.

## 민감정보와 운영 데이터

- 비밀값, 인증정보, 개인정보, 연결 문자열은 응답, trace, 로그, 커밋에 노출하지 않는다.
- 운영 데이터는 명시적 승인 없이 테스트 fixture나 생성 산출물로 복사하지 않는다.
- 비밀값이 필요한 작업은 기존 secret 관리 방식을 사용하고 비민감 식별자와 상태만 보고한다.

## 승인 거절·실패 처리

- 승인이 거절되면 해당 행동을 수행하지 않고 승인 없이 가능한 범위의 결과만 보고한다.
- 권한이나 sandbox 제한을 우회하지 않는다.
- 승인된 행동이 실패하면 같은 범위의 안전한 재시도만 수행한다. 대상, 영향, 비용이 달라지는 재시도는 다시 승인받는다.
- trace에는 승인 대상, 요청 시점, 사용자의 결정, 실제 수행 여부를 민감정보 없이 기록한다.
